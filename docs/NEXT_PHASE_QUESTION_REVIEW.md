# 下一阶段任务：题库逐题复验

以题目 ID 为单位，对照原件核对题干和选项，独立求解，再验证网站的判分结果。每批复验都应能从题号追溯到原件、推导和最后采用的答案。

## 范围与推进顺序

- 基线题库版本为 `pdf-8b725f83ff6497f2`，共 8,425 题。待复算清单取自 [逐题审计数据](../data/question-audit.json) 中 `mathematics` 为 `not-independently-recomputed` 的 8,130 条记录。开始新批前按当前审计重取清单，并核对它与当前题库的版本一致。
- 已对照原件复验 1.1「函数」原题第 1–8 题。下一批从原题第 9 题（`s-6b82188494c1-q0009`）接续，按题库的章节顺序推进，通过题目 ID 区分原题和补充题。已完成的 11 道重复选项修订沿用其现有记录。
- 建议每批 50 题。遇到图形题、长证明或原件缺损时，可以缩小批次，按实际处理的题号交接。每批保存下一道待复验题的 ID，以及需要另行查找原件的题目 ID。

## 每道题的验收标准

1. **对照原件。** 按来源链接、原 PDF 页码或补充题号定位，逐项比较网页和原件的题干、条件、图表及所有选项。特别核对正负号、指数、端点、定义域、极限方向和「正确／错误」「一定／可能」等容易改变题意的字词。原件存在多个版本时，记录本次使用的来源和关键差异。
2. **独立求解。** 先从核实后的题干推导，再与来源参考字母、网站答案和解析比较。计算题保留足以复查的中间步骤和适用条件。概念题说明定理条件，必要时给出反例。符号计算可用于条件明确的题，记录计算表达式、假设和得到的结果。
3. **检查四个选项。** 确认单选题恰有一个正确选项。检查不同写法是否数学等价，以及选项在边界条件下是否同时成立。修订重复选项后，重新验证每个新选项、解析和答案字母之间的对应关系。
4. **验证最终题目。** 对修订题检查网页中的公式、图片、题干及选项是否完整可读。验证选择正确项时得分、选择其他项时不得分。仅供查阅的题应继续排除在判分流程外。

## 选项和解析的呈现

- 所有题目的选项和解析优先使用可编辑文字与 LaTeX 公式。复验时，将原件中能确认的纯文字或公式截图转成文字与公式。原图含有解题所需的示意图、坐标图或其他无法用文字完整表达的信息时，保留图形，并用文字说明相关条件。
- 适合计算的题，优先用 MATLAB 辅助生成或复核选项数值、解析中的计算结果和图形。记录使用的表达式、参数、假设和关键命令，确保能重算。结果整理成可读的文字与公式，并核对单位、精确值与近似值及选项唯一性。
- 概念题、证明题和需要处理边界条件的题，解析应写明依据、推导或反例。使用 MATLAB 的题目也要在解析中说明关键推理，让读者能顺着步骤复核答案。

## 发现问题时的处理

| 情况 | 处理方式 |
| --- | --- |
| 原件清楚，网页转写有误 | 按原件修正相关字段，再用正确题干验算。 |
| 答案字母或解析有误 | 保存原参考字母，写入复算过程和修正依据。答案需要改动时，使用现有的 `correctedAnswer` 字段。 |
| 选项重复或有多个正确项 | 在保留考点的前提下更换干扰项。若歧义来自题干条件，同时修正条件，并在记录中说明改动。 |
| 原件缺页、图片损坏或关键条件无法确认 | 记录缺损位置和能验证的部分。无法可靠作答的题设为仅供查阅。按已确定的考点补编时，明确标注补编内容并独立验算，保留原件链接和来源记录。 |

## 逐题记录与批次交接

逐题核对及修订写入现有的 [题目复核记录](../data/question-reviews.json)。沿用 `sourceLabel`、`sourceSha256`、`referenceAnswer`、`assessment`、`kind`、`reason`、`method` 和 `parts` 等字段。通过题目 ID 在题库中定位来源链接和页码。`parts.analysis` 保存实际推导。只把需要修正的题干和选项写入相应的 `parts` 字段。来源有缺损时，在 `reason` 写清缺损字段及处理依据。

| 批次交接项 | 应记录的内容 |
| --- | --- |
| 范围 | 题库版本、章节、起止题号和实际处理的题目 ID |
| 本批结果 | 已核对原件并独立验算的数量，已修正题目及改动摘要，仍待确认的题号及原因 |
| 验证 | 公式渲染与判分结果，以及本批运行检查的结论 |
| 续做位置 | 更新后的待复算数量、下一题 ID，以及需要补找原件的题目 ID |

每道题同时具备原件核对证据、独立推导和判分结论，才计入完成数量。结构扫描、答案字母比对和公式可渲染各自作为辅助证据。遇到无法核实的题，记录当前状态并继续处理后续题目。全量交付时，逐项核对基线清单，列明完成情况及尚需原件的题目。

## 每批收尾检查

1. 复核本批编辑记录的源摘要、原参考答案和实际判分。用 `python3 scripts/question_reviews.py` 将修订应用到题库。
2. 用 `python3 scripts/count_questions.py` 和 `python3 scripts/question_difficulty.py` 更新派生数据。若本批调整了补充解析登记，同时运行 `python3 scripts/supplemental_analysis.py`。用 `python3 experiments/pdf-documents/export_markdown.py` 同步文字版。
3. 用 `python3 scripts/audit_questions.py` 更新逐题审计。如果本地保留的符号筛查结果版本已过期，先在含 SymPy 和 ANTLR4 的环境里运行 `python3 experiments/pdf-documents/audit_math.py`。
4. 运行题库检查、静态构建和站点校验，确认生成产物使用同一个题库版本。对修改过的题做针对性的渲染和判分验证，再更新批次交接记录。

```sh
python3 scripts/check_bank.py
python3 scripts/build_static.py
python3 scripts/verify_site.py
npm test
```
